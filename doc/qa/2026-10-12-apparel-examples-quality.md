## 可执行的真实测试路径

优先在隔离的、已获授权的非生产 HTTP 环境运行本分支，准备分支所需完整迁移、兼容 `generation-worker`、私有 Storage 和测试账号。由用户在该环境的安全 Secret 页面填写独立 `ZIMAGE_SEEDREAM_PLAN_API_KEY`，或通过执行环境的秘密注入机制提供；不经聊天、命令行明文、仓库或日志传递。Web 聊天 Key 保持独立。用户只需告知安全配置已就绪，执行者只报告存在性。

电商链路：`/create/product-set` 上传商品参考 → 保存可审核方案 → 明确确认三个选中项 → `/api/creative-tasks` 的 submit → `commerce_dispatch`/共享生成队列 → Worker → Plan Provider → 私有 Storage → 页面与原图下载。采用销售用途时必须保留真实商品引用要求，不能以修改准入规则绕过。若仅有 AI 参考，则测试明确命名为“合成参考一致性”，不能称真实商品保真。

聊天链路：唯一 `/` 工作区的聊天模式 → 开启图片工具 → 发送有明确生成意图的请求 → `/api/chat` → `createChatTurnRunner` → `imageService.submit(source='chat_tool')` → 共享生成队列 → 同一 Worker/Plan Provider → 页面与原图下载。当前聊天入口固定 1:1、2K、1 张；明确意图分支直接入队，不应额外消耗文字模型调用。

若只有安全注入的 Plan Key，可先使用仓库 `buildSeedreamRequest`/`generateSeedreamImage` 对预先记录的提示词做供应商原图检查。这能证明接口和输出像素质量，**不能**证明上述 UI、上传、RPC、Storage、扣费或聊天入口通过。必须在报告中标注“Provider-only”，不能替代两条项目链路。

## 判定及证据规则

每张分别给“通过 / 不通过 / 未测”，技术成功和视觉质量分开。检查颜色、款式、材质、轮廓、可见标识与主要结构；明显改变商品事实即保真失败。检查人体/服饰畸变、准确文字、完整主体和留白、角色构图、指令遵从、原始像素清晰度、边缘与重复纹理伪影。文字漏字错字、严重人体畸变或明显改款均判不合格，其余问题注明用途限制。四张小样只能说明这些单例，不推算全产品合格率。

原图在 100% 像素观察，另检查领口、袖口、衣袋、扣子、面料、手部和中文区域。页面 360px WebP 缩略图压缩单独记录，不能用缩略图发糊判原图失败，也不能只看缩略图认定原图清晰。保存原始响应图字节、SHA-256、真实模型/接口、请求与生成 ID、尺寸、开始/结束时间、耗时、实测入口、原始和缩略图对照及逐图判定；只保留非敏感元数据。
