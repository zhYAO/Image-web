## Candidate selected for one local QA build

Use an explicit opt-in production-webpack profile; default and development behavior remain unchanged. Exact-match aliases detach optional branches already disabled by the single application Markdown call: Mermaid/HTML preview, GitHub alerts, LaTeX and raw HTML, plus unused full-featured code chrome. Guards throw if a disabled branch is accidentally invoked; code fences still use the original highlighter. All client Shiki languages, themes, engine and loaders remain unchanged. Server Shiki supplies identical public metadata only: current Lobe hooks already return null under typeof window undefined. Version and metadata equality checks pin the assumptions.

For Next tracing only, exclude next-server paths setup-dev-bundler.js and next-dev-server.js. Generated standalone sets isDev:false; the two imports are guarded by opts.dev/options.dev. Their build/dev descendants include esbuild, font CSS fallback metrics and Babel. Do not exclude the entire Next build directory or a dependency based solely on its name. The read-only static graph model suggests36,797,636 dependency bytes, not business bytes; actual output must confirm.

Rejected for this candidate: fewer highlighting languages, a web-only language bundle, different regex engine/forgiving semantics, broad sideEffects:false, dropping fonts/Sharp, static export, and moving assets/dependencies to another layer to make the measured number appear smaller. Fullfonts33,444,454 and libvips18,699,288 individually exceed10MB in the present self-contained runtime.

Candidate was built once and measured below. No10MB success is claimed.

## Official references checked2026-10-27

- [Next output tracing](https://nextjs.org/docs/app/api-reference/config/next-config-js/output): NFT inspects import/require/fs; exclusions change traced copy contents, not already emitted chunks. Project16.4.1 source, rather than current16.4.3 defaults, governs the candidate.
- [Next package import optimization](https://nextjs.org/docs/app/api-reference/config/next-config-js/optimizePackageImports): named-import optimization; lucide/antd already default-optimized in pinned source. Existing deep Lobe imports are retained.
- [Next serverExternalPackages](https://nextjs.org/docs/app/api-reference/config/next-config-js/serverExternalPackages): native require changes placement, while standalone still needs the dependencies; no hidden byte savings.
- [Webpack tree shaking](https://webpack.js.org/guides/tree-shaking/): ESM export analysis and side-effect metadata govern removal. Broadly disabling side effects can lose CSS or initialization, so not used.
- [Shiki bundles](https://shiki.style/guide/bundles): main entry already lazily imports languages/themes; async files still count in dist. Language-limited presets reduce coverage.
- [Shiki regex engines](https://shiki.style/guide/regex-engines): alternatives have compatibility and token behavior requirements. Existing engine is retained.
- [Next static export limitations](https://nextjs.org/docs/app/guides/static-exports): dynamic request/cookie/server features and default image optimization make a direct export unsuitable for the current authenticated API application.

## Why the remaining target is not yet met

Remaining client grammar implementation is roughly8.74MB of literal data, plus
full themes/WASM, React/Markdown/UI and client application code. Server additionally
retains Sentry instrumentation1.59MB and the backend/API/framework code. None can
be removed solely because it is large. Client theme narrowing might remove about
1.36MB but would require a separate explicit theme contract and still not reach
10MB. Static export would remove required server features. Moving these remaining
modules to node_modules or external URLs changes accounting, not complete required
content; every such shared layer must still be listed.
