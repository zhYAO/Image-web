## 架构与修复

继续采用 Vite 静态前端、Next API、Supabase/Worker 与同域 Nginx。共享单一工作区、状态和网关比重写后端更适合当前项目；本轮重点是开发、运行时故障恢复、数据契约和发布闭环。

- 新增 `dev:split`：启动并验证本地 API 身份，再启动独立前端；同源代理保留 Cookie、Origin 和 SSE。前端子进程不继承服务端密钥。
- 显式运行环境接口替代共享源码字符串替换；旧 Next Mock 与独立前端 HTTP 使用同一工作区实现。
- 服务不可用时仅重查两个安全 GET；不兼容组合保持阻止，不重放生成请求。
- 电商访客登录回跳保留路径，账号页通过应用内导航返回工作区。
- 策划及上架文案结构移入 domain，新增可选 `expectedModules`，在计费完成前拒绝缺失、重复及未知模块；旧请求仍可省略该字段。
- 结构化结果校验数字、单位与完整型号。边界回归包括 `24Pro/24Max`、`128GB/128TB`、`500/500吨`、`5g/5G`，保留 `500ml/500mL/500毫升` 等价写法。此保护不构成对材质、功效等自然语言事实的语义证明。
- 详情模块提供自动文案、指定文案、不显示文字，保留旧方案的缺失、空字符串和非空字符串存储含义。
- 补齐首装 B1→F1 只读验收、开放前撤销 F1 及成对恢复入口；不生成虚假的 B0 收尾或已加载 ingress 证明。
