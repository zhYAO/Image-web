# Required PR check for future protected-merge release

Configure required GitHub check context `zimage-release-pr-required`, sourced from **GitHub Actions**, not "any source". Workflow: `.github/workflows/release-pr-required.yml`. Resolve the numeric `app.id` from GitHub's actual first successful check run and pin it in both the effective rule and the independent verifier; do not guess the ID. This required check has no path filters, conditionally skipped job, credentials, mutating permissions or deploy steps. It does not make an unprotected branch protected or grant approval.

Before a production authority can rely on this check, fetch the effective main rules (including applicable organization rulesets, bypass actors and enforcement) through an independently authenticated read-only observer with access to those records. Fail closed for missing/incomplete rules, unrestricted direct push, bypass, or force push. Verify the exact GitHub PR association and merged result SHA, main ref/source, base repo numeric ID, approved manual merger numeric ID, and an explicit completed/success Check Run from the expected GitHub App and approved workflow. Source App pin alone is not proof that a repository-controlled workflow was trusted; verify workflow identity or require its protected rules. Bind test SHA to the GitHub merge-test SHA (or other explicitly reviewed merge method) and test-result tree identity to the actual merge SHA; do not accept caller-selected check SHA, skipped, or neutral. Current rules do not prove past enforcement; establish the trusted policy before granting admission and hold activation on inconsistent observations. Verify exact release provenance and host rollback separately. Do not remove production environment review until root-managed paired admission is operational and rejects unsupported evidence.
