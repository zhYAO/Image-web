## Delivery boundary

- Deliver Phase 1 for desktop Web on Next.js 16 and Vercel.
- Preserve the existing narrow-screen layout as a regression target only; do not add mobile-specific features, PWA behavior, or a second information architecture.
- Use the dedicated Supabase Cloud project `image-web` for development Auth, Postgres, Storage, Queues, Cron, and Edge Functions.
- Keep `diagram/` untouched because it predates this implementation and is currently untracked.

## Execution order

1. Capture a fresh repository baseline and close known Phase 1A gaps.
2. Add anonymous SSR auth, migrations, explicit grants, RLS, sessions, timeline, quota, private assets, and cleanup foundations.
3. Add direct image generation through a durable queue and one-generation-per-worker execution.
4. Add Doubao/MiniMax chat SSE, Seedream/Gemini image adapters, three versioned skills, health windows, and Sentry correlation.
5. Add CI, Vercel Preview, provider benchmarks, real browser evidence, review artifacts, and regression evidence.

Every behavior change follows red-green-refactor. Each vertical slice must include its UI, public contract, persistence, error handling, and tests before the next slice starts.

## Locked contracts

- `/` is the only workspace; `/chat` and `/image` remain redirects.
- `POST /api/chat` accepts `{ sessionId?, message, tools?, chatModel?, imageProvider?, skillId?, images? }` and returns SSE.
- `POST /api/image` accepts `{ sessionId?, prompt, provider?, model?, params, skillId? }` and returns `202 { sessionId, batchId, status: "pending" }`.
- `POST /api/image/recreate` accepts `{ batchId, mode: "single"|"failed"|"all", generationId? }` and returns a new batch with HTTP 202.
- Errors use `{ code, message, retryable, correlationId, details? }`; details are allow-listed and redacted.
- Uploads and generated assets are private. Generated assets expire after 90 days, reference uploads after 30 days.
- Image submission is idempotent per `(user_id, idempotency_key)`. Unknown provider acceptance is never automatically resubmitted.
- Provider/model capabilities are versioned in the repository; deployment-specific model IDs are supplied through environment mappings. Phase 1 does not dynamically discover models.

## Quality gates

- Lint, typecheck, build, unit/component/contract tests, at least 70% coverage, pgTAP, migration/type drift, RLS negative tests, and Playwright must pass.
- Doubao, MiniMax, Seedream, and Gemini each run at least 30 fixed real samples after a one-call probe and under a hard call cap.
- Release-candidate evidence covers the latest two Chrome, Edge, and real Safari versions through a cloud browser service; WebKit remains a fast PR regression target, not a Safari substitute.
- Real Sentry events and alert replays cover browser, Route Handlers, and Edge workers.
- Supabase Pro platform backup and a real joint restore remain external production-release gates. Passing Phase 1 is not a production-readiness claim until those gates are closed.
